Chatlog is a local, provider-agnostic context layer for coding agents: it turns Claude Code, Codex, Pi, OMP, ChatGPT, and Anthropic activity into portable evidence, governed insights, and bounded context for later sessions. This repository is a local, governed memory compiler — immutable redacted evidence is canonical; indexes, conversations, derived reports, and memory are replaceable projections. Pre-release `v0.1.0-rc.1` is ready for local evaluation; storage formats and operator workflows can still change before `v0.1.0`.

### Canonical evidence boundary

`SourceAdapter.adapt()` emits an immutable `EventBatch`. Events retain provider and harness provenance, source paths and positions, native identifiers, adapter recipe, capture-policy version, semantic loss, and typed relations. Conversations are deterministic compatibility projections generated by `src/conversation-projection.ts`; they are not an authority.

The corpus manifest (`corpus/manifest.json`) is the authority for active source mappings. Each mapping records the canonical event-batch hash and conversation projection hash (with `contentHash` retained for legacy pointers). SQLite stores rebuildable event and conversation projections and must fail closed when its active receipt differs from the manifest.

Reasoning and opaque provider events remain evidence but are excluded from ordinary message full-text search, insight mining, handoffs, and context delivery. No provider payload is stored unredacted.

Ingestion reads provider histories without modifying them and never writes beneath `~/.claude`, `~/.codex`, `~/.pi`, or `~/.omp`. Corpus and analysis files are mode 0600 inside mode 0700 directories. Imports stop if the source or proposal changed after their preview (hash-sealed receipts); `chatlog source recover` resumes pending operations after a crash, and `chatlog source reconcile` reconstructs missing active analysis rows.
